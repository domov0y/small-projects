# Техническое задание: Launchpad
**Версия:** 1.1  
**Тип:** веб-приложение для управления homelab  
**Цель:** создать с нуля рабочий прототип, который можно установить в один LXC-контейнер и реально использовать.

---

## 1. Роль исполнителя

Исполнитель — автономная языковая модель-разработчик.  
Он должен самостоятельно спроектировать, написать, проверить и упаковать весь проект.

Требуется создать согласованный набор реальных файлов, который можно установить и запустить.  
Нельзя ограничиваться примерами кода, макетами, заглушками API или описанием архитектуры.

Исполнитель обязан:

1. Создать структуру проекта.
2. Реализовать базу данных и миграции.
3. Реализовать серверную библиотеку функций в `lib/`.
4. Реализовать HTTP API.
5. Создать веб-интерфейс на PHP + HTML + CSS + jQuery.
6. Создать тестовые страницы API.
7. Реализовать очередь заданий и worker.
8. Реализовать SSH-скрипты и тестовый скрипт.
9. Написать и запустить доступные проверки.
10. Подготовить инструкции установки.
11. Собрать готовый архив проекта.

Если в среде нет MariaDB или SSH — создать тесты, выполнить всё доступное и явно указать, что не удалось проверить.

---

## 2. Назначение системы

Launchpad — единая веб-панель для управления несколькими независимыми серверами homelab.

Через веб-интерфейс пользователь должен уметь:

- добавлять, просматривать, изменять и удалять хосты;
- описывать операционные системы и сервисы (сущности);
- назначать сервисы на хосты;
- управлять каталогом команд;
- назначать команды типам сущностей и отдельным хостам;
- запускать разрешённые команды на удалённых хостах;
- просматривать состояние заданий и историю выполнения;
- проверять работу системы через тестовые страницы.

Все хосты равноправны. Иерархия хостов не поддерживается.  
Docker-управление не требуется.

## 3. Технологический стек

**Обязательно:**

- ОС: Debian 12 или Ubuntu 24.04 в LXC-контейнере
- Веб-сервер: Nginx
- PHP: PHP-FPM 8.x
- База данных: MariaDB
- Серверная логика: обычный PHP (без Laravel, Symfony и других крупных фреймворков)
- Клиентская логика: jQuery + JavaScript
- Разметка: HTML5
- Стили: CSS
- Удалённое управление: SSH
- Фоновые задания: отдельный PHP-worker
- Формат API: JSON

**Дополнительно:**

- Не использовать Node.js как обязательную часть приложения
- Не требовать сборки frontend
- jQuery должен быть локальной копией (не CDN)
- Использовать PDO + utf8mb4
- Все основные функции должны работать без внешних облачных сервисов

## 5. Что устанавливать в LXC-контейнере

Рекомендуемая ОС: **Debian 13** 

```bash
apt update && apt upgrade -y

# Веб-стек
apt install -y nginx
apt install -y php-fpm php-cli php-mysql php-xml php-mbstring php-curl php-zip

# База данных (в первой версии — в этом же контейнере)
apt install -y mariadb-server mariadb-client

# SSH и утилиты
apt install -y openssh-client sudo curl wget git unzip
```

Рекомендации:

Создать системного пользователя launchpad (без login shell)
PHP-FPM и worker запускать от пользователя launchpad
Каталог логов: /var/log/launchpad/ (создать заранее)
Каталоги config/, lib/, scripts/, bin/, database/ не должны быть доступны через веб-сервер
Доступ к приложению и особенно к тестам ограничивать по сети или через Nginx

## 7. Модель данных
### 7.1. entities
Справочник типов объектов (ОС и сервисы).

- id
- name
- kind — os или service
- description
- created_at
- updated_at

Начальные записи: Linux (os), Nginx (service).
### 7.2. hosts

- id
- entity_id — ссылка на сущность типа os
- name
- address
- ssh_user
- ssh_port (по умолчанию 22)
- description
- created_at
- updated_at

Пароли SSH в базе не хранятся. Используется аутентификация по ключу.
### 7.3. host_services

- id
- host_id
- entity_id — ссылка на сущность типа service
- display_name (необязательно)
- port (необязательно)
- created_at
- updated_at

### 7.4. commands

- id
- name — название на кнопке
- script_key — ключ из белого списка
- arguments_json — дополнительные аргументы (JSON)
- description
- enabled
- created_at
- updated_at

script_key — логический ключ, а не путь к файлу.
### 7.5. entity_commands

- entity_id
- command_id

### 7.6. host_commands

- host_id
- command_id

### 7.7. jobs

- id
- host_id
- host_service_id (nullable)
- command_id
- status — queued, running, succeeded, failed
- arguments_json
- created_at
- started_at
- finished_at
- exit_code
- log_path
- error_message

Правило удаления хоста: запрещать удаление, если есть связанные задания (историю сохраняем).

## 9. Очередь и worker

- Нажатие кнопки в интерфейсе создаёт запись в таблице jobs со статусом queued.
- Worker (bin/worker.php) в бесконечном цикле:
- забирает одно задание (с блокировкой строки)
- переводит в running
- запускает скрипт из белого списка через proc_open (массив аргументов)
- пишет stdout/stderr в /var/log/launchpad/job-{id}.log
- ставит succeeded или failed + exit_code

- Одновременно выполняется не больше одного задания.

- Белый список script_key → путь к скрипту хранится в конфигурации.

- Путь к скрипту нельзя передать из браузера или API.

## 10. Скрипты
Обязательные скрипты первой версии:

- scripts/do_nothing.sh — тестовый скрипт. Просто пишет сообщение в stdout и завершается с кодом 0. Нужен для проверки всей цепочки без SSH.
- scripts/ssh_host_status.sh — проверка доступности хоста и базовой информации.
- scripts/ssh_restart_nginx.sh — перезапуск Nginx через sudo systemctl restart nginx.

Скрипты должны корректно возвращать код завершения.

## 11. Тестовые страницы
Каталог tests/ содержит простые страницы, которые:

- отправляют реальные HTTP-запросы к API;
- показывают метод, URL, тело запроса, код ответа и тело ответа;
- показывают результат PASS / FAIL.

### Минимальный набор:

- тесты хостов (CRUD + валидация)
- тесты сущностей
- тесты сервисов
- тесты команд (включая проверку белого списка)
- тесты заданий (создание, статусы, лог)
- проверка, что worker выполняет do_nothing.sh

Тестовые данные должны иметь префикс test_ и очищаться после себя.

## 12. Веб-интерфейс
Минимальный набор страниц:

 Главная — список хостов
Карточка хоста:
информация о хосте
список сервисов
кнопки команд (ОС + хост + сервисы)

место под будущие графики метрик (заглушка)


Все операции выполняются через JavaScript (jQuery) и API.

## 13. Безопасность (минимум для v1)

config/, lib/, scripts/, bin/, database/ недоступны через веб
Только prepared statements
Экранирование вывода в HTML
Проверка всех входных данных на сервере
CSRF-защита для изменяющих запросов
Белый список script_key
Логи заданий отдаются только через API
Доступ к приложению ограничивать сетью или Nginx
Не хранить пароли SSH в базе

Авторизацию пользователей в v1 не реализуем, но оставляем точку расширения.
